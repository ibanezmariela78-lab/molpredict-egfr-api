Quiero construir el backend profesional de una aplicación llamada “MolPredict EGFR”.

IMPORTANTE

En esta primera etapa quiero crear únicamente una API backend.

No crear frontend.
No crear páginas React.
No crear autenticación.
No crear base de datos.
No integrar AWS todavía.
No entrenar todavía un modelo QSAR real.

El frontend ya fue creado externamente en Lovable y posteriormente consumirá esta API.

OBJETIVO

Crear una API pública en Python con FastAPI para:

- validar estructuras químicas mediante SMILES;
- canonicalizar SMILES;
- generar representaciones moleculares 2D;
- calcular descriptores fisicoquímicos reales mediante RDKit;
- evaluar criterios orientativos de Lipinski;
- devolver una predicción demostrativa de actividad frente a EGFR;
- consultar moléculas similares de un pequeño dataset local demostrativo.

La validación molecular y los descriptores deben ser reales y calculados con RDKit.

La predicción de actividad todavía será demostrativa y debe estar identificada claramente como no validada científicamente.

TECNOLOGÍAS

Usar:

- Python 3.11 o una versión estable compatible;
- FastAPI;
- Uvicorn;

- logging estándar de Python.

No utilizar Flask.
No utilizar Streamlit.
No generar una aplicación visual.

ENDPOINT 1

GET /health

Debe responder:

{
  "status": "ok",
  "service": "molpredict-egfr-api",
  "environment": "development",
  "demo_mode": true,
  "rdkit_available": true,
  "version": "0.1.0"
}

Comprobar realmente si RDKit está disponible.

ENDPOINT 2

POST /api/v1/molecules/validate

Entrada:

{
  "smiles": "COc1ccc2ncnc(Nc3ccc(F)c(Cl)c3)c2c1"
}

Validar el SMILES utilizando RDKit.

Si es válido devolver:

{
  "valid": true,
  "input_smiles": "",
  "canonical_smiles": "",
  "molecular_formula": "",
  "atom_count": 0,
  "heavy_atom_count": 0,
  "message": "Estructura molecular válida"
}

La fórmula molecular debe tener formato químico correcto, por ejemplo:

C22H24ClFN4O3

No escribir incorrectamente CL en lugar de Cl.

Si es inválido, devolver un error HTTP 422 claro y seguro.

ENDPOINT 3

POST /api/v1/molecules/descriptors

Entrada:

{
  "smiles": ""
}

Calcular realmente con RDKit:

- molecular_weight;
- logp;
- tpsa;
- h_bond_donors;
- h_bond_acceptors;
- rotatable_bonds;
- aromatic_rings;
- fraction_csp3;
- formal_charge;
- atom_count;
- heavy_atom_count;
- ring_count;
- lipinski_violations.

Devolver también una evaluación de Lipinski:

{
  "criteria": [
    {
      "name": "Peso molecular",
      "value": 0,
      "threshold": "<= 500",
      "passes": true
    }
  ],
  "passed_count": 0,
  "total_count": 5,
  "summary": ""
}

Utilizar como criterios demostrativos:

- peso molecular <= 500;
- LogP <= 5;
- donantes de hidrógeno <= 5;
- aceptores de hidrógeno <= 10;
- enlaces rotables <= 5.

Aclarar en la respuesta que estos criterios son orientativos.

ENDPOINT 4

POST /api/v1/molecules/render

Entrada:

{
  "smiles": "",
  "width": 500,
  "height": 350
}

Generar con RDKit una estructura molecular 2D.

Preferentemente devolver SVG generado por el servidor.

La estructura debe:

- tener enlaces químicos;
- mostrar etiquetas de heteroátomos;
- mantener buena legibilidad;
- tener fondo transparente o blanco;
- estar centrada.

No devolver una red abstracta ni una imagen mock.

Validar los límites de width y height para evitar solicitudes excesivas.

REGLAS PARA LA PREDICCIÓN DEMO

- Debe ser reproducible.
- No usar números aleatorios diferentes en cada solicitud.
- Puede utilizar valores demostrativos predefinidos para los compuestos incluidos en demo_compounds.json.
- Para otros compuestos, utilizar una respuesta demostrativa determinista basada en el SMILES canónico.
- No presentar esa lógica como un modelo científico.
- No llamarla machine learning real.
- Indicar siempre prediction_mode="demo".
- Indicar siempre scientifically_validated=false.
- No inventar métricas de rendimiento.

Usar este disclaimer:

“Predicción demostrativa no validada científicamente. No reemplaza ensayos químicos, biológicos, toxicológicos, preclínicos ni clínicos.”

La conversión matemática entre pIC50 e IC50 debe ser consistente.

Si se fija una pIC50, calcular correctamente la IC50 correspondiente.
